## สรุป feedback กรรมการ = 6 ข้อ

| # | กรรมการขออะไร | ระดับความสำคัญ |
|---|---|---|
| 1 | ศึกษากฎหมาย + ข้อบังคับทางการแพทย์ให้ละเอียด กำหนดชัดว่าผู้ดูแลแต่ละระดับทำอะไรได้/ไม่ได้ | **สูงสุด — กรรมการพูดซ้ำ 2 ครั้ง** |
| 2 | จำกัด scope ให้แคบ แบ่ง segment ผู้ป่วย (เช่น ช่วยเหลือตัวเองได้ vs ติดเตียง) แล้ว map: ความต้องการต่อระดับ → สิ่งที่ผู้ดูแลทำได้ → แพลตฟอร์มเชื่อม 2 ฝั่งยังไง แล้วเลือก 1 อันมาโฟกัสก่อน | สูง |
| 3 | เก็บ data จากการใช้งานเพื่อหาโอกาสขยายบริการ (พาไปหาหมอ, รับส่ง) ออกแบบการเก็บ data ตั้งแต่แรก | กลาง |
| 4 | บริการแบบนี้มีคู่แข่งแล้ว — ศึกษาคู่แข่งรอบด้าน หาจุดที่เราเหนือกว่าชัด ๆ + มองกลุ่มเป้าหมายเฉพาะเจาะจง กรรมการเห็นโอกาสในโมเดล "ขับเคลื่อนด้วยพลังชุมชน" | สูง |
| 5 | ความปลอดภัย: มาตรการคัดกรองกัน "สวมรอย" เป็นผู้ดูแล + แนวทางรับมือเมื่อผู้ดูแลสร้างปัญหา/ก่อความเสียหาย | สูง |
| 6 | ขั้นถัดไป: ทำงานกับผู้สูงอายุจริงเพื่อสำรวจความต้องการ, รับสมัคร+อบรมผู้ดูแล (ถ้าจำเป็น), ทดสอบบริการความเสี่ยงต่ำ (ส่งยา, พาไป รพ.) ให้ครบกระบวนการ | สูง |

## ความเสี่ยงที่ทีมต้องยอมรับตรง ๆ

| ความเสี่ยง | ทำไมสำคัญ |
|---|---|
| **ขอบเขตกฎหมาย** | พ.ร.บ.วิชาชีพการพยาบาลและการผดุงครรภ์ จำกัดการปฏิบัติงานนอกสถานพยาบาล "งานดูแลทั่วไป" ไม่ใช่เส้นแบ่งทางกฎหมาย ต้องมี list งานที่ทำได้/ห้าม ที่ผ่านการตรวจโดยพยาบาล + นักกฎหมาย |
| **ความไว้ใจ / ความรับผิด** | ส่งคนแปลกหน้าเข้าบ้านคนเปราะบาง เคสขโมย/ทำร้าย/บาดเจ็บ 1 เคสจบแบรนด์ ไทยไม่มีระบบเช็คประวัติอาชญากรรมแบบ consumer ง่าย ๆ — ตรวจประวัติ สตช. ต้องขอความยินยอม + ใช้เวลาเป็นสัปดาห์ |
| **Cold-start ฝั่ง supply** | marketplace 2 ฝั่ง พยาบาลรับงานนอกอาจผิดสัญญาจ้าง รพ. / จรรยาบรรณสภาการพยาบาล supply จริงที่เป็นแกนคือ PN/NA ไม่ใช่ RN |
| **จุดต่างยังบาง** | "self-service แบบ Grab" — เอเจนซี่เดิมทำแอปเพิ่มก็ได้ moat ต้องเป็น supply ที่ verify + แบ่งระดับ + segment เฉพาะ + ความหนาแน่นเชิงพื้นที่ |
| **Unit economics** | คอมมิชชัน 15–60 บาท/งาน เทียบกับต้นทุน background check + support + ประกัน ที่แพงต่อผู้ดูแล ต้องโชว์ว่ากี่งาน/ผู้ดูแล/เดือน ถึงคุ้ม |
| **ประกัน** | liability insurance สำหรับงานดูแลที่บ้านโดยคนไม่มีใบประกอบฯ อาจรับประกันไม่ได้ในระยะ seed — ต้อง verify ไม่ใช่สมมติ |

## แผนงานรอบถัดไป (ร่าง)

- [ ] **1. เอกสารกฎหมาย 1 หน้า** — ขอความเห็นผู้เชี่ยวชาญกฎหมายสุขภาพ/สภาการพยาบาล
      ผลลัพธ์: list งานที่ทำได้ (ADL: อาบน้ำ ป้อนอาหาร พลิกตัว พาเดิน เป็นเพื่อน)
      vs ห้าม (ทำแผล ฉีดยา สายให้อาหาร ดูดเสมหะ — หัตถการทุกชนิด)
- [ ] **2. เลือก launch segment เดียว** — เสนอ: ผู้สูงอายุที่ยังช่วยเหลือตัวเองได้ ต้องการ ADL +
      เป็นเพื่อน + พาไปหาหมอ ในพื้นที่ กทม. โซนเดียวที่หนาแน่น (ติดเตียง = phase 2)
- [ ] **3. ตารางเทียบคู่แข่ง** — Health Delivery พา / VNurseCare / CareGiver.in.th / เอเจนซี่ท้องถิ่น
      แกน: ราคา, รูปแบบจอง, ความลึกการ verify, ขั้นต่ำเวลา, การแบ่งระดับ, พื้นที่ให้บริการ → ช่องว่างที่เราเติม
- [ ] **4. เอกสาร safety protocol** — วิธี verify ID + ใบประกอบฯ, ขั้นตอนตรวจประวัติ สตช.,
      check-in/out + GPS ในแอป, การ escalate ฉุกเฉิน, incident report → เคลมประกัน, rating 2 ทาง, นโยบายแบน
- [ ] **5. แผนทดสอบที่แน่นขึ้น** — คง survey 200 ครัวเรือน + 50 ผู้ให้บริการ
      เพิ่ม: ตามติดผู้สูงอายุจริง ≥ 5 เคส + pilot "พาไปตามนัด รพ." ครบ 1 รอบ (ความเสี่ยงกฎหมายต่ำสุด ตรงกับที่กรรมการชี้)
- [ ] **6. Unit economics 1 หน้า** — take rate, จำนวนงาน/ผู้ให้บริการ/เดือน ที่ break-even,
      CAC ผ่าน refer จาก รพ. เทียบกับยิงแอด, map เข้ากับงบ Phase-1 (4,000) / Phase-2 (8,000)
- [ ] **7. หาเกณฑ์ตัดสินทางการรอบถัดไป** ก่อนออกแบบสไลด์/งาน — อย่าเดาน้ำหนักคะแนนเอง
